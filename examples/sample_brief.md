# Sample brief — CivicLink (fictional learning example)

> **FICTIONAL SAMPLE.** CivicLink, its content, and its workflows below are invented solely to demonstrate how to write a project brief. There are no real customer testimonials, data, metrics or product claims here.

## Problem and users

Build a concept for a small community services directory that helps residents find the right public-service category without scanning a large homepage. Primary users browse from mobile devices. The primary action is **find a service category**.

## Scope

**In scope for concept exploration:** information architecture, navigation models, section layouts, responsive behavior and clear search/category discovery.

**Out of scope:** authentication, payments, data collection, backend changes, production publication, any real user records or automated scraping.

## Design constraints

- Calm and trustworthy rather than futuristic or decorative.
- Meaningful visual hierarchy; typography and icons chosen consistently.
- No decorative emoji, giant repeating card grids or misleading claims.
- Mobile-first layouts supporting keyboard and touch.
- No invented statistics, businesses, reviews or addresses. Use labelled mock data only.

## What to produce

Three concepts that differ in at least three structural dimensions: hierarchy, information architecture, navigation, content presentation and interaction model. Each includes a desktop and mobile wireframe, primary task flow, accessibility risks and implementation difficulty.

No code until one concept is explicitly approved. Any future prototype lives in a separate test environment.
