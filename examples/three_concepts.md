# Three different concepts — CivicLink (fictional illustration)

These are **text-only conceptual sketches**, not actual designs, screenshots, shipped features or independently scored outcomes. They demonstrate structural difference rather than superficial palette changes.

## A. Search-first utility

- **Hierarchy:** search is the first action, results are organized by service need.
- **Desktop composition:** compact masthead + central search + results with short factual summaries.
- **Mobile composition:** sticky search + linear results with descriptive labels.
- **Navigation:** query → matching service group → service details.
- **Risk:** low-information searches can frustrate people who don't know what to type.

## B. Guided need-finder

- **Hierarchy:** a short question replaces the search box as the first decision.
- **Desktop composition:** narrow guided sequence beside a progressively updated explanation panel.
- **Mobile composition:** one question per screen with previous/back controls.
- **Navigation:** need selection → 2–3 short choices → relevant service group.
- **Risk:** a guided flow can obscure alternatives; always provide an exit to browse.

## C. Category atlas

- **Hierarchy:** all service families are immediately visible, with descriptions and a clear secondary search.
- **Desktop composition:** asymmetrical category index and an adjacent detailed reading pane.
- **Mobile composition:** expandable category sections rather than a dense equal-card grid.
- **Navigation:** category index → details → related service families.
- **Risk:** too many categories increase scanning burden; information architecture must be tested.

## Structural comparison

| Dimension | A | B | C |
| --- | --- | --- | --- |
| Entry point | Search query | Need question | Category index |
| Information order | Results first | Progressive disclosure | Overview first |
| Navigation | Search to detail | Multi-step guide | Browse to detail |
| Desktop layout | Search and result list | Split guide and explanation | Category rail and reading pane |
| Mobile layout | Search with linear results | Step screens | Expandable groups |

These concepts still require research, prototypes, user feedback and real QA. Do not give them a passing accessibility or usability score on the strength of the prose alone.
