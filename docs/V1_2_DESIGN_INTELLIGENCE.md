# CreativeCode Engine v0.2.0 — Design Intelligence pilot

> **Scope:** V1.2 extends the existing prompt/review toolkit with an offline, deterministic concept architecture generator, a structural-difference heuristic, an evidence-gated critic packet, and a real project brief used in a **separate demonstration**. It is **not** an AI model, universal originality detector, code generator or production deployment system.

## Quick start

Requires Python 3.10+, stdlib only. Run from the repo root:

```sh
python3 -m creativecode concepts --brief examples/portfolio_brief.json --out examples/portfolio_concepts.json
python3 -m creativecode originality --concepts examples/portfolio_concepts.json --out examples/portfolio_originality.json
python3 -m creativecode critique --brief examples/portfolio_brief.json --concepts examples/portfolio_concepts.json --out examples/portfolio_critic_packet.json
python3 -m unittest discover -s tools -p 'test_*.py' -v
```

The CLI supports `portfolio`, `directory`, and `product` project types, each with three curated architectures. The generator preserves supplied content order and constraints but does not invent details. It produces repeatable design **starting points** from a controlled structural library. To get novel model reasoning, use `prompts/v1_2_creative_model.md` with an AI assistant, revise the generated JSON, and rerun the checker.

## Data contract

`examples/portfolio_brief.json` contains `project_id`, `project_type`, `project_name`, `audience`, `primary_goal`, `primary_action`, `constraints` and a nonempty list of `content_items` each with a `title`. Real assets must be independently verified. Avoid passwords, private client data, fabricated metrics and copyrighted third-party media in public briefs.

`examples/portfolio_concepts.json` contains a `concepts` array. Each record has `id` plus five required structural fields:

- `hero_structure`
- `information_architecture`
- `navigation_model`
- `content_presentation`
- `interaction_model`

The checker compares these declared labels case-insensitively. Every pair must differ on at least three dimensions. It flags a small, explicit list of `anti_patterns` if recorded. **Changing a label without changing the layout can falsely pass**; this is why a human must check the visual preview.

`examples/portfolio_critic_packet.json` deliberately sets all subjective ratings to `null` and unverified functional/accessibility gates to `not_tested`. A real independent critic must provide evidence before converting this into a `tools/score.py` review.

Approved facts used: MD Faysal Ahmed identity, editorial black/crimson design direction, English default with Bengali option, and featured work order SellDibo → DoharNawabganj → Nishabdo → DN Connect (in development) → Bangladesh Number Plate Maker. | | A — Editorial flagship | B — Project dossier | C — Cinematic chapters |
|---|---|---|---|
| Primary emphasis | Creator identity | Project evidence | Narrative chapters |
| Hero | Asymmetric identity + photo placeholder | Small masthead + active project | Large typographic manifesto |
| Information order | Identity → long-form work → about | Select work → dossier → supporting info | Manifesto → numbered chapters → work |
| Navigation | Simple section anchors | Numbered project index and active pane | Chapter index with skip links |
| Content | Editorial project rows/stories | Selectable dossier | Chapters with chronological index |
| Interaction | Scroll to work | Change selected project | Jump between chapters |
| Key risk | Long reading path | Hidden details and keyboard affordances | Motion / performance burden |

Static demonstrator: open `examples/portfolio_preview/index.html` locally. It is a sandboxed concept viewer, not generated by the Python engine and not a finished website. It deliberately uses no real portrait or project screenshots. It supports the three concept views and English/বাংলা switching.

See [`V1_2_PILOT_REVIEW.md`](V1_2_PILOT_REVIEW.md) for recorded pilot QA evidence and open limitations.

## Actual verification and limitations

- Schema validation, deterministic outputs, missing-field errors, preserved content order and pairwise declared-structure checks have automated tests.
- HTML concept preview can be tested in a local browser but does **not** establish user preference, visual novelty or professional quality. Browser evidence and screenshots must be recorded separately when run.
- No actual LLM call, research browsing, usability study, commercial licensing check, production merge or real portfolio deployment is performed by the engine.
- A concept direction must be approved by a human before turning the selected variation into production code.
