# Phase 3 — Real user testing protocol

**Version:** v0.2.0 · **Current evidence:** no independent tester results recorded yet. This document is a study plan, not proof of adoption.

## Study targets (not achieved metrics)

Recruit 5 independent developers familiar with AI-assisted coding. Seek 3 unassisted completions and 2 actionable written reports. Do not ask anyone for stars, upvotes, confidential files or private client details.

## Two-minute browser test

1. Share only the [live demo](https://faysalishere.github.io/creativecode-engine/). Ask testers to locate the three concepts without coaching.
2. Ask which two approaches differ in hierarchy, navigation or content presentation.
3. Have them use the on-page [guided test](https://faysalishere.github.io/creativecode-engine/#quick-test), including the **Not sure** option.
4. They may copy their notes and post to [feedback issue #1](https://github.com/faysalishere/creativecode-engine/issues/1). GitHub sign-in is required to comment, but not to try the demo.

A useful attempt explains a real difference **or** an area where the distinction is unclear. This is not an aesthetic quality or accessibility certification.

## Optional Python test

Give testers [QUICK_START.md](QUICK_START.md), Path B. Verify whether they generate `concepts.json` without assistance. Record the **specific command and error** if they fail; do not request secrets or full private terminal history.

## Consistent feedback questions

- What were you trying to design? (portfolio / directory / product / other)
- Which structure would you explore, or **Not sure**?
- Could you tell the concepts apart? (clearly / partly / not yet)
- Did the browser test and optional CLI work without assistance?
- What *one improvement* would make CreativeCode useful on a real project?
- Would you use it again? Why?
